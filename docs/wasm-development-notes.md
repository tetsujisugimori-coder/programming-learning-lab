# 教材制作から学べること

## なぜWATを選んだか
CやRustを先に学ぶ必要なく、Wasmの命令を短く読めるためです。WATはブラウザーが直接実行するJavaScriptではありません。WABTが文字を解析し、型のつじつまを確認し、バイト列へ変換します。

## ブラウザーAPIとJavaScriptの役割
WebAssembly.compileはバイナリを検証・コンパイルします。instantiateは実行できるインスタンスを作ります。JavaScriptが入力値を検査し、公開されたcalculateを呼び、戻り値を画面へ表示します。Wasmの計算命令だけでボタンやDOMは操作しません。

## 難しい設計
正しい構文でも無限ループは作れます。そこでUIとは別のWorkerに変換と実行を置き、UI側の時計で停止します。メモリを無制限に安全に扱える保証ではありません。また、古いコードの結果を新しいコードの成功と表示しないため、編集・移動・再実行でWorkerと成功記録を無効化します。

## 人間はAIのコードをどう検証するか
まず2+3の予想を書き、実行して5を確認。次に命令だけsubへ変えて−1を確認します。入力と命令を同時に変えないことが理由の説明に役立ちます。括弧不足、型の食い違い、unreachable、無限ループも意図して試し、成功に見せないか確かめます。画面の「成功」だけでなく検証ログ・コード・実際の操作を照合しましょう。

## 制作から学べること
データとUIの分離、非同期通信、状態の寿命、例外処理、再現可能な依存固定、幅に応じた表示、テストの限界です。読了したこと、クイズを解けたこと、実行できたことは同じではありません。結果の理由を自分の言葉で書くことが最後の確認です。
